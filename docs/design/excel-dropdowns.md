# 새 데이터 파일의 엑셀 유효성

`drtable new`가 새로 만든 통합문서에만 데이터 유효성을 기록한다. 기존 파일을 발견하면 쓰기 전에 거부한다. 데이터는 4행부터 입력하므로 적용 범위는 4~1,048,576행이다. 열거형 목록은 선언 순서를 유지한다. 쉼표로 합친 목록이 255자를 넘거나 열거자에 쉼표가 있으면 숨긴 `#Lists` 시트의 셀 범위를 참조한다.

숫자 규칙의 양 끝 포함 범위, 한쪽 경계와 문자열 `len<=N`을 엑셀의 정수·소수·텍스트 길이 유효성으로 옮긴다. `fixed<N>`은 엑셀에 입력하는 소수 값에 소수 유효성을 적용한다. `required`와 `regex`는 build 검사에 맡긴다. 배타적인 양쪽 경계, int32로 정확히 표현할 수 없는 경계도 build 검사에 맡긴다. 엑셀 유효성은 입력 보조 수단이며 붙여넣기 등으로 우회할 수 있으므로 build 검사를 계속 사용한다.

`Ref<T>`의 키 드롭다운은 `--input`으로 데이터 루트를 명시했을 때만 만든다(0.12.0). build와 같은 `load_model`로 모든 파일·중첩 폴더를 읽으므로 일부 파일만 보고 키를 빠뜨리지 않는다. 데이터 오류가 있으면 만들지 않는다. 목록은 생성 시점의 키이므로 유효성 오류 형식을 '경고'로 둬 새 키 입력을 막지 않고, 메시지로 그 점을 알린다. 키는 숨긴 `#Lists` 시트에 쓰며, 정수 키는 숫자로 써서 입력한 숫자와 일치하게 한다. 대상 키가 10,000개를 넘으면 드롭다운 없이 경고한다. 배열 참조와 스트링 참조는 대상에서 제외한다. 서브키 참조는 그 열의 서로 다른 값을 목록으로 쓴다. 0과 빈 이름은 '참조 없음' 값이라 목록에서 뺀다(빈 서브키 칸은 기본값으로 바뀌어 들어온다). 같은 목록은 `#Lists` 열 하나를 함께 쓴다. 2^53보다 큰 정수는 엑셀 숫자로 정확히 담을 수 없어 글자로 쓴다. CLI와 GUI는 `commands::new_workbook` 하나를 쓴다.

배열은 새 파일에서 쉼표 입력 셀 하나로 생성하므로 원소 단위 유효성을 적용하지 않는다. 기존 파일의 `Field[0]` 같은 원소 열은 이 명령이 수정하지 않으며 build가 원소별 규칙을 검사한다.
