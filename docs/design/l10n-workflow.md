# 번역 작업 흐름 설계 메모

## 입력과 진행률

`l10n`은 입력 폴더의 스트링테이블 스키마와 원본 `Strings/*.xlsx`를 읽는다. 기존 `load_model`로 스키마·키·참조를 검사한 뒤, 진행률은 원본 셀을 다시 읽어 계산한다. 빌드 모델은 빈 번역을 기준 언어로 채우므로 그 모델의 값으로 빈 칸을 셀 수 없다.

테이블과 언어마다 `전체`, `채움`, `비어 있음`, `기준과 같음`을 센다. 기준과 같음은 채운 수에 포함한다. 기준 언어 자체는 모든 칸이 기준과 같다. 텍스트는 공백을 제거한 셀 값으로 비교한다. 결과는 테이블·언어 순서로 고정하고, JSON 필드 순서를 고정한다.

## 안 쓰는 키의 판정

일반 테이블의 `Ref<스트링테이블>` 필드 값은 해당 스트링테이블의 사용 키로 센다. 배열 참조의 각 원소도 센다. 일반 테이블의 `text` 필드 값은 모든 스트링테이블의 키와 비교한다. 같은 키가 여러 스트링테이블에 있으면 `text` 필드의 값은 모두 사용한 것으로 본다. 데이터 테이블의 어느 필드에서도 찾지 못한 스트링 키를 `테이블.키` 순서로 보고한다.

이 분석은 데이터 테이블만 훑는다. C++·블루프린트·런타임에 조합되는 키는 알 수 없으므로 결과는 삭제 후보를 찾는 용도다.

## 원본 보존

모든 명령은 입력 파일을 읽기만 한다. 가져오기는 새 출력 폴더 아래 파일을 만들며 원본 파일은 덮어쓰지 않는다. 동일한 출력 파일이 있으면 오류로 중단한다.

## 외주용 파일과 가져오기

`export`는 대상 언어의 원본 셀이 비어 있거나 기준 언어와 같은 키만 한 개의 `Translations` 시트에 쓴다. 열은 `Key`, `Base`, `Translation`, `Memo`, `Source`, `Sheet`, `Table`, `Language` 순서다. `Source`는 입력 폴더 기준 상대 경로다. 작업자는 `Translation` 칸을 채운다.

`import`는 `--input`의 현재 원본 스트링 파일을 다시 읽고, 번역이 채워진 행을 파일·시트·키·언어로 찾아 적용한다. 기존의 다른 키와 언어는 그대로 둔 새 워크북을 `--out` 아래 같은 상대 경로로 만든다. 원본에 없는 키는 건너뛰고 경고한다. 내보낼 때 기록된 `Base`와 현재 원본 기준 문구가 다르면 경고하되 번역을 적용한다. 빈 번역 칸은 건너뛴다. 가져오기는 원본의 셀 값과 시트 구성을 새 워크북에 재작성하며 서식과 수식은 복제하지 않는다.

번역 파일에 원본 전체를 넣지 않는 이유는 외주 파일 크기와 오래된 원본 값으로 되돌릴 위험 때문이다. 가져오기 시점의 원본을 명시적으로 지정한다.
